# Публикация и передача результата

Применяется при запросе публикации или завершения работы. Разрешение на коммит, push и PR определяется правилами AGENTS.md и текущим поручением пользователя.

1. Сверить `git status` с согласованным составом изменений. Для оставшихся файлов объяснить, к какой работе они относятся; чужие изменения сохранить. Проверить базовую ветку и незавершённые PR, от которых зависит текущая работа.
2. В итоговом сообщении различать локальную проверку, отправку кода, прохождение CI и публикацию. Для каждого заявленного результата привести проверяемое подтверждение: коммит, PR, запуск или артефакт. Локально прошедшие тесты не означают, что новая проверка уже работает в main.
3. При разрешённой публикации проверить триггеры `.github/workflows/publish.yml`. Изменение Python-кода само по себе сейчас не запускает Pages: после попадания нужного кода в main нужен ручной запуск workflow. Загрузка с портала проходит через сценарий Make (ADR 0007): его проверяют загрузкой изменённой выгрузки и сверкой нового коммита в `inbox/` и запуска workflow. Дождаться результата и сверить публичные HTML и XLSX с артефактами этого запуска. Дата данных может оставаться прежней при исправлении кода; одной даты или HTTP 200 недостаточно.
4. При показе локального портала собрать актуальные файлы в каталог, который действительно раздаёт сервер. Записать исходную выгрузку и версию кода. Уже открытая вкладка и прежняя `.scratch/site` не подтверждают результат текущей работы.
5. Остановить запущенные для задачи фоновые процессы по точным PID и проверить их дочерние процессы. Сохранить только явно запрошенные пользователем процессы, указав PID и назначение. Общие серверы Codex и процессы других задач не останавливать.
