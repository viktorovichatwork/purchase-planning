# Покрытие — по циклу заказа поставщика, сезонный товар — одним заказом на сезон

Пересчёт идёт ежемесячно по всему ассортименту, но заказ должен покрывать «плечо + цикл заказа поставщика + страховой запас», а не «плечо + 1 месяц». Компания реально заказывает партиями по поставщику раз в 2–4 месяца (медиана 30 SKU в заказе у главного поставщика, одна партия покрывает ~5 мес продаж), и морской контейнер не возят под один SKU ежемесячно; покрытие в 1 месяц при таком ритме гарантирует дефицит. Для сезонных категорий (space_heaters: 42% годовых продаж в октябре) регулярное пополнение не работает — дозаказ приходит после пика и лежит до следующего сезона, — поэтому для них решение принимается один раз на сезон с крайним сроком размещения.

Сезонной считается категория, у которой на 3 месяца подряд приходится ≥50% годового спроса: обогреватели, триммеры, лески и ножи. Решение принимается по категории: на уровне SKU тест даёт ложные срабатывания на мелких объёмах. Сезонный заказ покрывает окно сезона, то есть самый короткий непрерывный отрезок с ≥80% годового спроса. Три месяца для этого мало: за окном оставалось бы 15–40% спроса. Крайний срок размещения равен началу окна минус плечо поставки. Спрос вне окна закрывается обычным пополнением. Ровные SKU того же поставщика присоединяются к сезонному заказу, если их собственный цикл наступает в пределах ±1 месяца.

Пропущенный крайний срок показывается явно. Модель предлагает поздний заказ: прогноз только на месяцы окна после ожидаемого прихода, уровень сервиса сезонный, всегда «условно к закупке» и с прогнозом остатка на конец сезона. Если такой заказ покрывает меньше месяца пика или меньше минимальной партии, он помечается «не рекомендуется». Если приход после окна, поздний заказ равен 0 и показывается крайний срок следующего сезона.

## Considered Options

- Ежемесячный заказ на 1 месяц покрытия — отвергнут: противоречит фактическому ритму поставок и контейнерной логистике.
- Чистая точка заказа по SKU — отвергнута: заказ всё равно собирается по поставщику.
