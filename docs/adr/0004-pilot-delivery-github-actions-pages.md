# Пилот: заказчик загружает выгрузку на GitHub, расчёт идёт в GitHub Actions, результат публикуется на GitHub Pages

Решение делается для заказчика, который ничего не устанавливает и не работает в Claude Code. Поэтому в пилоте заказчик загружает CSV из ERP через веб-интерфейс GitHub в папку `inbox/` репозитория. Это запускает GitHub Actions: проверка формата, детерминированный расчёт, проверки инвариантов, xlsx, сравнение с прошлым запуском, LLM-текст. Результат публикуется на GitHub Pages: первый экран, ссылка на xlsx, история запусков. Выгрузки и результаты запусков хранятся в репозитории, git служит историей. LLM вызывается через шлюз Experiential (platform.experientiallabs.ai) с ключом из секретов репозитория, правила ADR 0003 действуют.

Расчёт всегда идёт на дату среза выгрузки. Если выгрузка старше 35 дней, лист заказа публикуется как черновик.

Пилот сознательно открыт: публичный репозиторий и публичная страница. Это допустимо только на обезличенных данных и только до доказательства жизнеспособности; закрытие доступа отложено в backlog (issue #1).

## Considered Options

- Проектный skill `/plan-purchases` в Claude Code — отвергнут для заказчика: запускать его может только разработчик. Остаётся инструментом разработки.
- Общая папка Google Drive с опросом по расписанию — отвергнута: сложнее в настройке, результат появляется с задержкой. Это запасной вариант, если заказчику не подходит аккаунт GitHub.
- Приватный Claude Artifact — отвергнут для пилота: публиковать его можно только из сессии Claude, а не автоматически.
- Расписание без автоматического источника данных — отвергнуто: оно пересчитывало бы старый срез.
